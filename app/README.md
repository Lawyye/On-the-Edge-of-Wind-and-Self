# Edgewind — «On the Edge»

Flutter-приложение: место, где можно оставить свою историю без настоящего
имени и получить отклик от других. Android и десктоп.

Пакет: `com.ontheedge.edgewind`.

---

## Откуда взялся код

Исходники были потеряны вместе с компьютером, на котором писались. Уцелел
только `app-debug.apk`. Flutter в отладочных сборках кладёт в
`assets/flutter_assets/kernel_blob.bin` полный текст Dart-исходников — он нужен
виртуальной машине для стектрейсов. Оттуда всё и восстановлено. Из релизной
сборки так не получилось бы: там AOT-машинный код без текста.

## Как собрать

Платформенные папки в APK не лежат — их восстанавливает сам Flutter:

```bash
cd app
flutter create --org com.ontheedge --project-name edgewind .
flutter pub get
dart run flutter_launcher_icons     # иконка приложения
flutter run
```

`flutter create` в существующей папке дописывает только недостающее и не трогает
`lib/`, `pubspec.yaml` и `assets/`.

## Релизная сборка

Тот APK, что раздавался, был **отладочным** — отсюда и 185 МБ, и запуск по
10–15 секунд:

| | debug | release |
|---|---|---|
| Размер | 185 МБ | ~12 МБ на ABI |
| Dart | `kernel_blob.bin` 44 МБ, JIT при каждом запуске | AOT, скомпилирован заранее |
| Vulkan validation layers | 15 МБ, тормозят каждый кадр | нет |
| ABI | все три сразу | по одной |
| Запуск | 10–15 с | обычно меньше 2 с |

```bash
flutter build apk --release --split-per-abi
```

Готовое — в `build/app/outputs/flutter-apk/`, для большинства телефонов нужен
`app-arm64-v8a-release.apk`. Отладочную сборку раздавать не стоит: она медленная,
весит в десять раз больше и отдаёт весь исходный код любому, кто её распакует.

## Что нужно включить в Supabase

**Обязательно, иначе приложение не запустится:** анонимный вход.
Authentication → Sign In / Providers → **Anonymous sign-ins** → включить.

Приложение не спрашивает ни почты, ни телефона, ни пароля: оно открывает
анонимную сессию и привязывает к ней придуманное имя. Если провайдер выключен,
приложение честно напишет об этом на первом экране.

Адрес проекта и публикуемый ключ зашиты в `lib/data/supabase_config.dart`.
Ключ не секрет — он для того и предназначен, чтобы лежать в клиенте; доступ
решают политики RLS. Переопределяются при сборке:

```bash
flutter build apk --release --split-per-abi \
  --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...
```

## Оформление

Всё держится на одной мысли: **машина холодная, люди внутри тёплые.**

Обвязка — моноширинный верхний регистр, пластины с уголками, развёртка CRT,
янтарь на почти чёрном. А то, что человек написал своими руками, набрано
книжной Literata и остаётся единственным тёплым пятном на экране, поэтому
взгляд идёт к чужой истории, а не к интерфейсу.

Тёмная тема основная. Светлая сделана не инверсией, а «бумажной» распечаткой
того же терминала: янтарь уходит в охру, иначе на светлом он слепнет.

Отметка называется **«я рядом»**, а не «лайк»: ставится один раз, снимается
повторным нажатием и не выносится крупно — здесь не за что соревноваться.
Достижения выдаются за отклики другим и за возвращение, и ни одно — за
количество собственных тяжёлых историй.

## Данные

Истории, отклики, отметки, закладки и достижения лежат в Supabase, в таблицах
с префиксом `ew_`. Схема и правила описаны в `../supabase/README.md`.

Главное, что стоит знать, читая код: счётчики, модерацию и выдачу достижений
ведёт **база**, а не приложение. Клиенту нельзя доверять подсчёт того, на что
он сам влияет, поэтому прав на запись туда у него просто нет.
